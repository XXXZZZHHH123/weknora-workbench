# 结构化核对记录关联与页面加载修复

日期：2026-10-15。基线：`a2d4c6b`。

## 已核实的原因

知识库级目录隔离上线后，旧的空间级扫描记录没有迁入相应知识库。从知识库原件打开结构化解析时，系统只查找已经绑定原件 ID 的记录，没有识别同一空间内、相同原件的既有人工核对结果，因而重新扫描。原记录没有删除，但新页面显示了新扫描的状态。

服务器只读盘点确认：原空间保留 28 张可查询表，其中 14 张为人工确认；同一原文件在知识库中被重新扫描后仅有 15 张可查询表，人工确认数为零。两份原件的完整 SHA256 一致。

页面还存在两个独立问题：核对界面排在查询报告、指标和图表的加载之后；首次请求中登录凭证刷新时，失效请求没有重新初始化，可能需要重新进入页面才能显示。

## 修复行为

- 优先加载扫描摘要和原表核对界面；知识库 Excel 导入页不读取隐藏的数据报告、指标目录和图表。进入数据查询时再加载，切回导入保留已有 DOM 和草稿。
- 首次加载中凭证更新，使用新凭证重新初始化；旧请求不能把错误或其他空间的数据写回新页面。已加载的核对草稿不因凭证续期重建。
- 从真实原件打开解析时，先验证知识库读写权限和所属空间；仅检查该原件所有者空间的旧记录。只有重新校验后的原件完整 SHA256 一致，才复制该文件的核对映射、原文件、不可变数据快照和历史记录，不重新解析。
- 知识库 GET、同名文件、其他空间的相同文件都不能触发迁移。已有人工确认或已恢复记录不会被覆盖；多份不一致的历史记录要求显式选择。
- 新扫描结果保留；原空间不变；覆盖核对记录前另存备份。发布以核对记录最后一次原子保存为界，失败清理新复制快照，保留此前可用状态。

本改动不涉及问答意图分类或回答生成，不增加问题、商品、指标或列号规则。

## 验证

- 使用当前生产结构化镜像，在服务器另起不挂载业务卷、禁止联网的临时测试容器：468 项通过，19 项既有可选验收项跳过，另有 14 项子测试通过。
- 浏览器首次加载、查询按需读取、无需切页自动显示已恢复状态、首次加载凭证续期：7 项检查通过。
- 浏览器知识库隔离、草稿保留、凭证更新和旧入口兼容：14 项检查通过。
- 新增恢复测试覆盖：已绑定的新扫描、重新上传的相同字节原件、已有人工映射、错误原件、损坏快照、恢复幂等性、原文件和数据文件保持一致。
- 扩展的完整浏览器样式验收中，旧深色导入配色断言与当前固定浅色核对区不一致；本轮不修改该配色，也不把该样式项算作通过。新增首次加载回归和知识库隔离检查已纳入 CI。

服务器已恢复为 28 张可查询表、14 张人工确认；逐份核对原文件、字段目录和数据文件 SHA256，原空间保持不变。恢复前核对 JSON 备份保存在该扫描记录的 `recovery-history/` 中，新扫描快照也保留；应用加载逻辑通过正常源码发布生效，不向业务数据写入验收样例，也不改变其他空间。
