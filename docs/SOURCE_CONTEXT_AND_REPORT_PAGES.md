# 重复字段与指定报告读图

## 行为

普通问答、智能推理和表格分析共享字段发现与来源检查。问题出现真实 Excel 表头时，先返回对应字段目录，不把“20天原料”等已存在的名称自行解释成库存天数。重复字段保留不同原表列，附表头、合并表头及有限层级的公式引用来源；没有唯一匹配的口径时先澄清，不选择第一列，也不将它们相加。

`query_series`、`analyze_table`、`compare_series` 和 `convert_price` 接收应用签名绑定的真实用户问题，在执行数值查询前再次检查同名来源。模型提交的 `source_question` 会被本轮真实问题覆盖。明确原表列或唯一匹配的实际来源可以取数，“双29”仍对应两种来源时继续澄清。

来源上下文为可重建的派生缓存，原工作簿指纹检查通过后才读取；不修改原件、已发布的数据集或单元格公式，不执行公式、不访问外部工作簿。公式样本仅说明该单元格引用链，不证明整列历年公式不变，也不推定“20天”是自然日或交易日。

## PPT 图表和页码

PPT/PPTX 按演示文稿实际幻灯片顺序建立页码，根据每张幻灯片关系定位图片及 OLE 对象的缓存预览。EMF/WMF 转为清晰 PNG，保留所属页、媒体路径及原图文字；不刷新外部链接。配置 DocReader 时，旧 `anydoc` PowerPoint 规则也会走此路径；没有 DocReader 时保留原本的原生解析能力。其他文件类型的引擎选择不变。

可以确定坐标、线条颜色、唯一图例和单一线性纵轴的 EMF 折线图，额外提供依据原矢量记录计算的末端估读值、误差范围及排序范围。无法核验、双轴或非线性等情况不生成该表。估读不是行情原始数值；不同曲线各自末端的比较不冒充同一天的精确排名。

指定日期报告及页码时，搜索和读取绑定同一实际文件；缺失、存在多个活动候选或缺少页码证据时说明原因，不引用其他报告的同名图，不以文本分块序号猜页码。删除中、已删除及归档文件不能参与定位。长页返回继续读取参数，图片描述及 OCR 同时进入问答上下文。

## 完整回答

空回答、标点或在长推理后只有单个残片的结果会触发最多两次修复；用户明确要求的简短回答保留。数值核验和最终生成路径使用同一检查，未经核验的数字草稿不会先流到页面。原表完整字段名、单元格和完整公式作为来源身份处理，不把其中的规格代码、行号或常量授予统计值权限。

## 验收依据

- “20天原料”在棉花工作簿“纱布利润”中对应 C/F/U/X。C 引用“3128级棉花”；F 引用“双29棉花”，其公式引用“3128级棉花”；U 引用“CC Index 3128B”；X 引用另一组“双29棉花”，其公式引用“CC Index 3128B”。裸问题需澄清；“双29”不能唯一选择 F/X。
- 明确 CC Index 3128B 来源及 2016-04-07 时，原工作簿 U100 的缓存值为 11902 元/吨，日期来源 A100。验收直接核对原件，不以模型文字当作校验依据。
- 原“棉花周报20240310(2).pptx”第12页的“郑棉01-05价差”来自该页缓存图像，红线图例为 2401。矢量记录的末端估读约 210 元/吨，范围约 170～250；按图中各曲线自己的末端比较，低于 2201、1601，高于其余曲线。应注明估读及比较范围。

原业务工作簿未重新上传、未生成验收数据集版本。现有周报使用原文件重新解析，以修复旧索引；本地模型验收记录保存于忽略目录 `.build/header-chart-diagnosis/`。

## 本地验证

- Linux 结构化服务全套：376 通过，19 跳过，14 个子测试通过。macOS 全套中的工作进程资源限制测试无法设置 Linux 所需限制，按实际 Docker Linux 环境复验通过。
- Go agent、tools、modelcontext 及带 `anydoc` 的 docparser 测试通过；工具套件跳过一个本地构建容器缺少 Python `ensurepip` 的既有测试。
- PPT 页码、图片关系、OLE 缓存、几何估读及转换回归：21 通过，6 个旧文件夹具缺失而跳过。更广的 DocReader 套件另有本地假 IP DNS、缺 MHTML 夹具和进程组时序的环境失败；不据此声称全部 DocReader 测试通过。
- 原工作簿直接读取缓存值，并按共享公式的原始锚点独立展开：C100 `=B80`、F100 `=E80`、U100 `=T80`、X100 `=W80`，对应值分别为 12055、12355、11902、12202。未通过结构化服务或模型生成这一核对结果。

本地图表识别节点使用已实际验证可接收图片的 Qwen3.8 Flash；棉花知识库的后台摘要模型从长时间未结束的 GLM 改为已验证可用的 DeepSeek，原分块、存储和索引配置保留。原先“支持视觉”的配置标记不能证明服务真的接收了图片。问答模型仍使用用户配置的 `deepseek-v4.1-flash`。模型输出要和原图图例、原矢量记录或工作簿缓存核对，生成完整文字不等于验收通过。
