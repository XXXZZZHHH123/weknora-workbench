验证先在业务库只读备份上完成，随后备份本机数据库和旧程序，再应用修复二进制并重新创建原有临时 systemd 后端单元。本机后端健康检查通过，迁移记录仍是 40/clean，缺失结构已经恢复，4,462 条原分块逐列指纹一致、33 个原文档数量不变。旧失败文档没有被标记为完成，也没有自动重跑。

## 向量化错误与重试

此前 `BatchIndex` 的供应商错误大多被统称为 `VECTORSTORE_WRITE_FAILED`，不能仅凭页面文字断定向量数据库损坏。现在保留原始错误，明确区分 embedding 请求阶段与索引存储阶段；只有供应商真正的 HTTP 429 标记为 embedding 限流，向量库的 quota/429 不再被误判。

HTTP 400、401 等永久错误不再在同一批次中重复请求五次；429、503 和传输故障仍可按原预算恢复。保留任务队列原有重试及失败清理机制。该代码修复已在本机运行，但不代表云端供应商请求已经恢复；云端仍需部署版本、实际模型配置与底层错误日志才能判断。
