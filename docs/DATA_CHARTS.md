# 按真实数据绘图与 PPT 原图预览

普通研究对话提供 `render_chart`，用于从本轮已经成功读取的数据生成折线图、柱状图或散点图。它不调用图片生成模型，也不执行模型提交的代码。

模型先调用 `inspect` 查看实际数据来源句柄、列索引、单位、行数和完整性，再通过 `render` 选择来源、X/Y 列及图型。数据来自已授权的结构化查询结果、实际读取的文档 Markdown 表格，或本轮 `read_pdf_table` 取得的真实单元格。目录、字段说明、失败查询和模型自行编写的数字不能充当数据源；修改数据后旧来源句柄失效。

`inspect.input_sources` 中的 PDF 二维单元格须先 `map`。模型根据完整问题决定 `orientation`、`x_index`、`y_indexes`、`value_indexes`，程序验证并复制实际坐标，不接受模型填写观测值。`rows` 表示 X/Y 分别取原表行、观测跨列排列；`columns` 表示 X/Y 取列、观测按行排列。`rows` 必须提供 `label_index` 从原标签格取轴名；无原标签时改用引用真实源字段并显式命名的查询整形。`unit_index` 仅复制来源已声明且所选列一致的单位。返回的 `source_id` 可直接用于 `render`。原始行数与转置后的观测数可以不同；映射、原单元格、分页范围及覆盖限制保留。SQL 派生结果不能再次通过该操作丢弃依赖或技术身份标记。

PDF SQL 由 DuckDB 自身语法树检查输出表达式的真实源字段依赖，逐列区分源值、源行统计、常量标签、技术身份以及混入常量的观测。无来源的常量数组、只在未用的 CTE 中提到源表，不构成源表取数。数值轴只能采用源值或合法源行统计；标签常量可用于维度，不可冒充观测。保留原有只读、外部访问及资源限额。该检查不是逐单元格 SQL 血缘或任意表达式的代数影响证明；尚不支持的复合结构和集合生成形状明确拒绝，不能静默降级放行。

图表保持实际行序、原值及缺失断点，不填零、平滑或推造日期。时间轴要求原表实际 ISO 日期；缺少日期时使用原有类别标签。不同单位不自动合并或换算。图内仅保留标题、坐标、图例及必要的单位/部分范围标注，不嵌入解释段落、原始数据表或技术JSON；来源与核对数据保留在工具审计中。超预算时明确失败，不用截断样本冒充完整走势。

长表可在 `render` 中用 `series_column` 指定真实标签列，配合 `unit_column` 复制逐行声明单位；也可在 `map` 的 `columns` 映射中指定这两个索引。仍须显式选择 X 与一个数值 Y 列。程序仅按真实标签值拆成最多 6 条系列，图例逐字来自源单元格，不接受模型提交标签常量，不聚合重复的 X/系列观测，也不补齐缺失值。单位列只要有缺失，该系列就保持未知。查询关系中的 `metric`、`unit` 等实际字段可直接选取；无需用技术来源 ID 的 `CASE` 常量重写标签。技术 ID、常量观测及来源依赖保护继续生效。

类别折线图和柱状图要求每个 X 类别唯一；同一 X 下的多条业务系列须按真实维度拆列或显式聚合，不能只用汇总图例掩盖系列。散点图保留重复样本。SQL 角色判定区分控制条件与输出值来源：技术 ID 用于筛选真实观测，不会把输出观测误标成技术坐标；技术 ID 或常量本身作为输出仍保留相应保护。模型未被要求绘图时，可直接根据真实结果形成分析结论。

渲染及独立语义核验前确定性检查同轴 Y 单位：`mixed` 是来源已知冲突，不能降格为未知；显式单位不同同样拒绝，反馈要求按真实单位拆图或分开选取。`unknown` 表示没有确认单位，可展示原值，图片不显示其未确认单位，最终文字也不得声称单位。SQL 聚合、cast、标量乘除、一元正负和含混合分支的结果继续传播 `mixed`、原因与来源证据；声明单位和未知分支合并仍为未知。真实单位列不能抹去数值列已有的 `mixed` 冲突证据。

图表以确定性PNG图片保存到回复附件，可直接预览并下载。保存沿用现有资源目录、消息归属和权限下载；文件归实际发问者的会话，共享智能体的执行空间不改变附件归属。同一工具执行重复交付复用既有附件，删除后的附件不会因重试复活。生成成功与否以实际保存的附件为准。历史HTML附件保留原样。

保存前另有独立模型核验完整请求、近期对话、实际选中数据、坐标、单位、范围和图型。它须独立声明所需 X 轴类型，程序校验与实际参数一致；类别轴会等距排列，日期字符串本身不构成真实时间间隔。工具返回规范 `chart_spec`、全部 `selected_rows` 和映射记录，不能以标题正确或 PNG 存在替代语义核验。

语义核验同时查看未选中的真实来源列及对应全部行，以便发现被单个数值列或汇总图例隐藏的维度与逐行单位；超过既有输入预算明确拒绝，不静默抽样。不同度量混轴、应区分的维度未区分属于 `chart_issues`，不能放入 `pending_deliverables` 后放行。合法汇总图例仍由模型结合完整任务和真实数据判断，不按图例文本设禁用词表。

绘图和结构化读取共用真实进展检查，重复目录、相同真实查询结果及未扩大原来源坐标的映射不算新进展，失败计入停滞；新图实际保存才算交付进展。连续 3 个无新证据工具轮次要求重规划，6 个轮次停止工具；每轮另累计最多 4 次 `render` 未交付，成功不重置失败额度。停滞后仅在已有真实执行结果时进入无工具最终合成，纯目录或失败记录不触发额外合成；绘图上限、最大轮次与已有协作边界按同一收尾路径处理。收尾继续数字与引用核验，最多 60 秒，已有更小预算仍优先；模型失败或收尾超时提交非空失败说明。用户主动停止不再触发合成。

字段与图表目录在预算内保留完整条目和全部曲线的图例、类型、轴与单位；超过预算明确披露缺失，目录只提供来源发现线索，不能当作已执行的数值结果。

模型任务规划显式给出 `source_discovery` 和 `delivery_requirements`：恢复已讨论来源时仅发现工具协议，并在当前权限下重新读取真实来源；需要新搜索时使用模型结合上下文形成的独立检索语义。历史助手表格仅为意图线索，不作为观测事实。纯文本任务的低推理开销不适用于缺失或失败的图像交付，必要失败说明不能在删减过程中消失。

仅当图片通过上述独立核验、完整任务视图无遗漏且已满足全部交付要求，运行时才登记私有凭证。纯图片答复可在任务、真实结果、工具调用和精确 Markdown 仍匹配时复用该核验，减少重复大审核；公开结果 JSON 中的通过标记不能伪造凭证。任务变更、未核验图片输入、混合分析或其他文件交付保留普通完整性审核。

模型依据完整请求选择`delivery_mode`：默认`chart_only`只回复图片，不追加过程、解释、统计或建议，也不自动附加分析面板。用户明确同时需要文字分析时才用`chart_with_analysis`，保留相应分析展示；失败和无数据不伪装为成功图片。

该功能是对真实数值的确定性重绘。查看报告原有图表仍应打开来源预览，插画生成仍由单独的 `generate_image` 能力处理。

PPT 来源预览会将原文件内部的 OLE 缓存图片提升到浏览器可显示的预览副本，不打开外链或执行嵌入对象。解包、排版与显示在浏览器完成；EMF/WMF 仅在对应物理页进入视口或被引用时，通过现有受保护接口按源 SHA、物理页和媒体 part 转成 PNG。浏览器内矢量图请求统一限制为两个并发。替换直接作用于原图位置，保持页面布局和滚动位置；原文件字节及知识解析结果不变。

同一浏览器页面使用64MiB、128项、10分钟有效期的内存缓存，保留成功加载的原文件、预处理数据和PNG；关闭预览只释放该实例的object URL，重开可以复用字节。引用面板还会保留当前单份PPT的排版DOM，关闭时暂停媒体加载，重开仍先校验权限与文件版本；切换来源、回到引用列表、切换账号或离开当前会话时释放旧预览。每次打开先读取当前知识详情校验权限与文件版本，缓存还按登录凭据、激活空间、真实文件身份及源SHA隔离。失败不缓存，图像解码失败会淘汰相应PNG以便重试；切换来源或权限后，过期异步响应不能回填旧图。

关闭时已开始的至多两个共享转换请求可完成并填充缓存，其余已关闭视图的队列不再启动。缓存不写本地持久存储，刷新页面、超过有效期或容量淘汰后仍会重新请求；首次未缓存的矢量图仍由服务器转换，服务器已有独立的有界转换缓存。缓存命中不能替代每次打开的权限检查。

预览需要浏览器能计算原件 SHA（安全上下文，如 HTTPS 或 localhost），后端校验失败时不会用其它页或其它文件的图替代。实际完整性需检查图像解码和内容，不能仅凭页壳、logo 或 HTTP 200 判定图表显示成功。

绘图来源的审计信息与数据行分别限额。分析结果的输入审计说明过长时，仅将这部分元数据投影为全部输入的核心来源、单位、计数和范围引用，并保留完整审计信息的SHA256与明确的部分投影标记；实际数据行、列、SQL、源文件身份、输入/输出完整性均不改写。核心审计仍超过预算的来源继续拒绝，inspect返回有界拒绝原因与实际可用句柄，不把已查询但被拒的来源默认为没有数据。绘图使用inspect返回的chart-source句柄，不能用结构化结果ID替代。

最终数字核验只排除当前回合真实成功绘图附件在Markdown图片或下载链接目标中的精确资源地址；图片alt、标题及周围正文仍参与核验。伪造、失败或其他回合附件不产生数字依据，图片交付仍经过原有来源审核。

模型资源协议优先使用成功工具返回的已保存附件句柄或Markdown，即使同一结果另含文件名，也不得改写为sandbox地址。sandbox下载约定仅用于会话工作区中实际识别出的文件输出，不能由聊天里的文件名推断文件存在。
