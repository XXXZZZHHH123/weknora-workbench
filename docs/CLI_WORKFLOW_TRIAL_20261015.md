## 已改进流程

1. 增加独立预检：版本、隔离能力、认证文件存在性分别记录；只有符合严格结构的零 turns 原生报告可证明此次只读额度查询。目录、退出码和历史费用不再被当作剩余额度。
2. Gemini 额度须同时确认周与 5 小时桶可用，拒绝缺失、disabled、重复、负数、NaN、布尔和字符串等异常值；调用前收据最多 5 分钟有效且绑定模型/档位/版本。
3. Gemini 临时明确禁止额外 credits；Grok 本轮额度按用户单次确认记录，不虚构 CLI 实时余额。未知费用通道不会默认放行。
4. 补齐隔离设置失败、进程启动失败、版本不符和额度未确认的失败收据；只记录异常类型，不回显可能携带凭据的异常正文。
5. 生命周期区分准备、原生调用、候选检查，项目再记录接管和独立测试。调用耗时不能称为完整任务耗时。
6. 主代理复核后补上 `authentication_verified is True` 门禁，不能凭“本地认证文件存在”或失败收据中的缺失/false 状态放行。新增测试先观察五种错误认证状态被旧代码误放行，再修复转绿。
7. 原生 print 期限改为与外层期限联动：`外层 - min(30秒, 外层/4)`，默认仍为外层 210 / 原生 180 秒，不擅自延长或降档。明确原生 print 超时诊断单独记 `native_print_timeout`；即使 partial 符合 schema 或 native 报 SUCCESS，也不能验收，usage 标记不完整。

工具回归从 50 项增至 61 项，全部通过。五个破坏性变体均被测试捕获：未知额度放行、允许额外 credits、去掉在线认证门禁、恢复固定原生期限、放过超时 partial。独立 CLI 工具仓库的 8 个文件已由主代理完整审查，并独立重跑 61 项离线测试通过，形成仅本地提交 `e7e8f26`，未推送；工具工作区干净。其中没有业务源码或私有原始日志。

## 反馈

这次证明了隔离、额度查询和失败验收能落在真实任务上，也再次暴露 Antigravity“成功状态但空正文”的可靠性问题。应保留停止与 Codex 接管路径。现在没有证据说明这种拆分节省总时间或多少优质 token；小任务的预检、契约和复核成本可能超过收益。

Grok 的额度确认与特定私有源码的外发授权是两件事。自动审批拒绝后没有重发那份源码；后续改成不读源码的通用合成用例任务，再次经自动审批允许。本地修复和测试继续。此次只能如实报告“Gemini 空候选被拒收 → Codex 接管；Grok 私有源码审查被阻断，纯合成替代超时”，不能声称完成了双通道模型审查。

下次委托先记录输入来源 `synthetic/public/private-code`。私有代码检查具体目的地、片段和本次授权；确认额度不替代数据导出授权。已经授权的纯合成、无源码任务直接推进，不额外制造源码导出审批。

项目目录只保存脱敏契约、收据和汇总。原生 raw 保留在工具包 ignored `local-runs/`，凭据仅有临时副本并随调用清除。
