# 指标页三栏、自选与核心关注

状态：设计，开发中。依赖 [图表库与周期对比](CHART_LIBRARY.md)。是否已部署以目标环境实际验证为准。

## 背景

研究员同时关注单个指标和成型图表。图表库单独放在一个页面，和指标分开，不便于把两者放在一起管理；总览的"核心指标"只能放指标；很多关键指标（如基差、价差）存在于原表，却因所在工作表仍处于"待确认"而不在目录中，看起来像是缺失。

## 一、指标页三栏

本节与第二节已实现源码及隔离测试；浏览器交互待在可启动浏览器的环境验收，未部署。

- `/sn/indicators` 分为三栏：**自选**、**指标**、**图表**（`?tab=favorites|catalog|charts`）。默认打开自选；自选为空时打开指标。
- "图表"栏承载原图表库首页的内容：本周同期异动、分组、搜索、卡片、"从原表导入"入口。`/sn/charts` 跳转到 `/sn/indicators?tab=charts`；图表详情 `/sn/charts/{id}` 与导入页 `/sn/charts/import` 保持原地址。
- 顶部导航去掉单独的"图表库"，保留"指标"。
- 指标行、指标卡片、单指标页、图表卡片、图表详情页都有星标按钮，用于加入或移出自选。

## 二、自选（按账号）

- 自选按账号保存，在研究台内互不共享。记录在 `workbench_artifacts`（`module = "favorites"`），按 actor 隔离；每人每个研究台一条记录。
- 正文：`{"format": "favorites.v1", "items": [{"kind": "indicator" | "chart", "id": "...", "added_at": "..."}]}`，最多 100 项，顺序可调整。修改需带 `revision`，冲突返回 409。
- 指标 id 必须在当前研究台目录中，图表 id 必须是本研究台未删除的图表；读取时失效的条目标为"已失效"并保留，由研究员移除，不静默删除。
- 以前保存在浏览器里的自选（`tin.indicators.favorites.v1`）：账号自选为空且本浏览器有旧记录时，提示"把本浏览器的 N 个自选同步到账号"，研究员点击后才写入，不自动迁移。
- 自选栏同时列出指标和图表：指标显示最新值、变化和周期位置摘要，图表显示缩略图。
- 接口：`GET /api/sn/favorites`、`PUT /api/sn/favorites`（整表替换，带 revision）。受限视角返回 403。
- 首次读取返回 `revision = 0`；首次写入也需携带 0。条目读取结果附 `status: active|invalid`，仅将 `kind`、`id`、`added_at` 存入正文；已保存的失效条目可以保留、排序或移除，不能作为新条目加入。旧来源授权返回 409；无写权限账号可读、自选写入返回 403，个人自选不要求研究台共享编辑权限。
- 总览选择核心指标时仍自动加入自选，改为写入账号；移出核心不移出自选，也不自动同步旧浏览器记录。现有核心指标配置与上限不在本次扩展范围内。
- 自选使用上下按钮排序；指标默认调用自然年周期接口，同时显示最新有效值、较上期差值与同期排名。周期摘要和图表缩略图在进入视野附近时读取，共用最多 4 个并发任务。
- 隔离检查：Python `tests/test_favorites.py`、`tests/test_chart_pages.py`；Node `tests/favorites-client.test.cjs`、`tests/indicator-preferences.test.cjs`、`tests/native-catalog-v2.test.cjs`；浏览器 `tests/favorites-ui.cjs` 及更新后的图表、单指标、市场总览用例。浏览器夹具的 Python 解释器通过 `RESEARCH_PYTHON` 指定。

## 三、核心关注（研究台共享）

- 总览的"核心指标"改名为"核心关注"。它仍是研究台共享的配置，沿用现有存储（`SourceMapping` 的核心配置），扩展为 `{"items": [{"kind": "indicator" | "chart", "id": "..."}]}`，最多 16 项。旧格式 `series_ids` 读取时按指标条目处理；写回时使用新格式。
- 图表条目显示为小图卡：缩略图，加上周期模式下"同期第 k/(n+1)"和最新值。受限视角的核心关注只显示已授权的指标条目；图表条目一期在受限视角下不显示，并提示"图表条目暂不对受限视角开放"。
- "选择与排序"中可以从自选、指标目录和图表库中添加。

## 四、核心关注建议

- 核心关注为空时，显示"生成建议"。研究员点击后，由模型根据研究框架和当前目录的真实字段（名称、单位、频率、工作表）给出不超过 12 个建议，按"供给 / 需求 / 核心标的 / 库存 / 平衡 / 宏观"分组，每项附简短理由。研究框架与产业图生成使用的框架一致：核心标的看价格、基差或升贴水、期限结构、内外比价等多个维度。
- 程序只校验模型返回的 id 是否真实存在于当前目录、是否有重复、数量是否超限；不按指标名称、关键词或工作表名选择或补充指标（`AGENTS.md`）。
- 建议以勾选列表展示，研究员"采用所选"后才写入核心关注；未采用的建议不保存。
- 模型调用沿用研究服务现有的平台模型路径（同策略文字整理、产业图生成），记录调用审计；模型不可用时说明原因，不回退到固定列表。

## 五、待确认工作表提示

- 结构化服务新增 `POST /api/research/source-status`，沿用研究台来源核验，返回当前研究台每个来源原件中各工作表的核对状态统计（`confirmed`、`auto_ready`、`needs_review` 等），以及未确认工作表的字段数。只返回工作表名称、状态与数量，不返回数值。
- 指标栏顶部和核心关注为空时显示提示："知识库还有 N 张工作表待确认（含 M 个字段），确认后才能在这里使用"，并附链接到该知识库的表格核对页。
- 表格核对页提供"确认全部已检查通过的工作表"：先列出将被确认的 `auto_ready` 工作表（名称与字段数），研究员确认后批量提交；`needs_review` 不包含在内，仍需逐表核对。

## 六、验收

- 两个服务完整测试通过；新增测试覆盖自选的隔离、上限、失效条目、迁移提示、revision 冲突；核心关注旧格式兼容、图表条目、受限视角；建议的 id 校验与"不硬编码"约束；来源状态接口鉴权；批量确认只包含 `auto_ready`。
- 本机棉花研究台实测：三栏切换、星标加入自选、图表进入核心关注、生成并采用建议；确认"郑棉相关价差"等待确认表后，基差类指标出现在目录中。
