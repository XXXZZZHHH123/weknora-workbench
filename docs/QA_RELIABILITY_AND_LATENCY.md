# 问答来源核验与耗时回归记录

本记录对应 2026-10-15 的服务器问题。业务验收数据仅保存在隔离的测试夹具和本机 `.build/qa-latency/`，不向业务知识库上传样例或固定答案。

## 已确认的原因

服务器当时运行的应用为 `74b2458`，并未部署后续文档能力更新，因此不能将这次故障归因于新文档沙箱。

- 美国各州面积题总耗时约 110.5 秒：20 轮主模型约 49.4 秒，工具约 14.4 秒，轮次耗尽后的终止合成约 46.5 秒。它已读到报告，但继续查找未导入的 Excel 数据。
- 价格种类的旧会话耗时约 129.9 秒，其中模型轮次约 128.3 秒，工具总计约 1.3 秒。重复复核与思考没有持续增加证据。
- 新会话同题约 146.5 秒，包含额外查询与一次字段模型超时。请求初始化仅几十毫秒，目录发现约一秒，主要瓶颈不是请求排队。
- 文档工具向模型展示图片 OCR 和图注，而数值核验只读取片段正文；混合表格/文档回答因此漏失合法数值依据。
- 部分拒绝也是正确的：旧草稿把部分匹配目录的实际数量写成另一个总数，不能为通过验收而放开。

## 通用修复

1. 实际引用片段中的已读取图片 OCR/图注参与数值核验。没有引用的图片、失败工具、网址数字、文档嵌入的伪工具 JSON 不成为计算依据。
2. 待澄清结果只登记真实完整字段身份，不将尚未放行的数据变成统计结果。
3. 独立复核保留每个工具的有界结构化视图、身份、来源覆盖和明确的遗漏标记，避免整条大结果被静默丢弃；程序校验仍使用完整运行结果。
4. 实际读到文档正文也触发来源复核；不要求将报告已有的原文数值强行改查 Excel。模型理解表头、基期、舍入和口径，程序执行新增计算。
5. 复核结果使用明确的最终答复字段，先解 JSON，再还原引用和资源。草稿不当作交付正文；最终完整性、数值及来源检查继续执行。
6. 数字疑点在首次独立复核前提供，避免先盲审再开启修复；被复核替换的首稿不额外调用一次完整性模型，最终候选仍检查。
7. 只有明确的只读工具操作可以并行；绑定来源、字段确认、写入和未知工具保留执行屏障。
8. 字段目录提供按真实工作表与原指标名的分组计数，覆盖分页前匹配集合，并标明候选范围。程序不替模型判断哪些指标属于用户所问业务类别。
9. 断流恢复只有已完成工具记录时显示处理中，避免退回“请求已发出”。

文档新增计算使用 `calculate_source_values`：模型提交公式与来源计划，程序只接受本轮已授权实际读取的片段、逐字原文、完整数值及显式单位，以有理数执行批量四则运算。未知来源、拼接数字、无单位百分比、单位不一致、除零、函数/代码、超限输入均拒绝。它不访问任意数据库、不执行模型代码，也不推断业务含义；原文中的数据、模型的业务计划与确定性计算保持分离。

## 文档表格批量计算与交付边界

新增 `calculate_document_table`：模型根据真实已读分块选择表、行、列、单位和公式，程序从实际 Markdown/OCR 单元格批量计算，保留原始行、字段索引和精确结果。表格语法识别不判断商品、指标或业务意图。空值、不合法数值、零分母和解析停止明确报告，不补零；未知单位不能生成百分比。批量计算省去逐行重抄原值和引用的大参数；零散原文仍可使用来源绑定的四则工具。

两种计算协议均区分未知单位、有量纲、无量纲和已显示百分数；来源引用、行编号与任意元数据不作为额外计算结果。格式层只处理明确的答案响应契约：先解析答案对象，再还原来源和资源。终止合成使用同一契约，无效或不完整的对象不能作为已完成答复显示。

### 模型任务规划与工具按需展开

在真实来源发现后，普通工作台请求先由同一已配置模型执行一次独立规划：完整问题、近期实际对话、显式来源范围和真实工具能力目录作为输入，输出本轮目标、必要证据、工具名称和完成条件。该调用局部关闭思考、温度为0、最多768输出token、12秒超时；不改变管理员保存的主回答温度或思考配置。

程序只检查协议、预算、真实工具名和发现引用，不按问题词、商品、日期或指标决定来源。有效计划仅收窄本轮向模型展示的工具定义，不删除注册工具、不改变执行权限；模型始终可以通过 `expand_task_tools` 查看实际完整能力并恢复后续需要的工具。新增用户指令清除旧计划和投影，避免之前的查数计划限制新的文档生成。非法、截断、不可用或超时计划完整回退到原工具集。实际已注册的通用来源发现与绑定工具始终可见，避免粗计划遗漏依赖后失去修正来源的入口；是否查询及选择何处仍由模型判断。

规划内容、工具定义、schema中的数字均不能成为数值依据。来源绑定、权限、真实ID、单位、计算和最终完整性校验继续执行；计划声称完成不等于真实执行完成。纯能力展开是状态屏障，不与其他工具并行修改能力集合。规划不会缓存问题答案，也不预存样例流程。

常驻的来源能力还包括实际已注册的文档表格检查和结构化原生工具，避免规划遗漏真实schema后错误调用网关。实际字段目录和来源片段保留在规划视图，纯工具schema不重复占用来源视图预算。来源待复核的工作台技术草稿局部使用温度0；普通未取证对话和自定义智能体保留原采样设置，管理员配置不被写回修改。

### 同次最终核验检查来源含义

旧的最终完整性检查明确不核验事实含义，因此即使18行数值全部通过，附加解释仍可能偷换指标或把OCR排版提取问题说成原图错误。现在对有本轮真实来源的普通工作台答复，将来源一致性并入原有完整性调用，不另加一轮检查。它核对完整请求、实际指标和口径、单位、范围及来源层级；正文、OCR、图注、原图实际返回和在生成上下文中的可见性分别提供运行时元数据，不把图片网址等同已看过原图。

检查器只能返回是否通过及有界修复意见，不能增加事实、执行工具或替代数值校验；意见明确为模型意见，不写入来源或数值池。无请求或无依据的附加结论优先删除，已有证据足够时修正答复，不为了附加内容重新取数。沿用最多两次修复；未通过候选不向用户展示为最终正文，程序失败提示也不触发额外复核循环。非工作台原有严格完整性协议保留。

文档表格执行前用同一表达式文法和单位代数预检一次公共公式，避免无效公式按每行重复执行并返回大量重复错误。预检不计算占位来源数值；实际行仍独立验证真实数值、未知单位、精度与零分母，缺失值不补零。合法的 `a/(a-b)` 不会因为预检占位值相同而被误拒，实际零分母仍拒绝。

计算记录的行身份另提供独立8KB摘要，保留真实表格、范围、原计数和实际执行行标签，明确预算遗漏；不提供新值、不分类业务对象，也不进入数字池。模型据实际标签核对明细与总计/小计是否已计入，避免把包含总计的记录数表述成同样多的明细另加总计。

剩余耗时已按真实日志分开：154.52秒那轮中，读取20个已解析文档块实际仅10毫秒；其后约38秒是模型生成18行重复标量计算参数（2644个输出token），并非文件读取/OCR或队列等待。该调用因引用单位不完整被拒绝，后续批量工具仅需短计划。工具参数生成、重复复核与模型首字等待仍有波动，不能将局部修复称为稳定秒级。

另用同一价格会话追加Word/PDF请求验证工具投影：实际展开生成能力并生成两份文件，144.63秒后返回真实资源引用；这证明能力未被新计划切断，不代表文档生成性能通过。

### 文档表格模型计划执行

新增 `analyze_document_tables`。工具只接收空对象，不接收替代用户问题、主模型扩写的子任务或任意执行计划；服务器传入完整原问题、真实对话、明确来源范围和已持久化的用户追加指令。一次隔离模型调用从真实已读表的完整行、表头和单位生成1至4个批量计划，程序复用原 `calculate_document_table` 执行器检查真实分块、索引、范围、单位与四则运算。明确的手动计划仍可使用原工具。

模型只看当前来源绑定内成功 `read_document` 的数据，先前读取不能绕过后续文档或物理页码限制。目录和表格行独立有界；未完整进入视图的表不能执行猜测计划。计划模型局部关闭思考、温度0、20秒预算、最多2048输出token，不改管理员配置；同一JSON协议也写入隔离提示，兼容仅执行JSON模式的服务商。句柄只通过原计算工具的所属参数策略解码 `chunk_id`，不对单位、公式或其他原文字面值做全局替换。

输出只包含真实子执行：`ok`表示所提计划技术执行成功，仍不证明完整业务覆盖；`partial`保留真实成功项、失败及范围，不能冒充完整。数值池仅接纳实际工具身份下成功的规范计算结果，不接纳计划、schema、模型建议或失败槽位，原始运行Data优先。来源一致性摘要同时覆盖实际成功子执行。新工具保留串行屏障；模型调用用量计入本轮。

80.41秒的真实验证仍发生一次严格JSON计划失败和一次表达式/单位计划失败，均未放行。后续修复补齐隔离调用可见的完整协议和技术错误反馈；最终代码已通过本地Go回归、相关并发回归，并在本地Docker实际调用确认。只描述已观测错误类别，不把泛化错误臆断成某个具体非法字段或公式。
