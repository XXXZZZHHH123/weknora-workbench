# PDF 表格结构化导入

PDF 正文仍按原有文档检索链路处理。数字表格可以另行进入结构化工作台：保留 PDF 原件、解析器原始产物和逐页表片段，核对后生成逻辑表，由只读 DuckDB 查询。向量检索用于找文档，不能替代精确表格计算。

## 使用流程

1. 在知识库打开 PDF 原文预览，点击“核对 PDF 表格”，直接在当前预览的弹窗中操作，无需跳转结构化数据库模块。也可在结构化工作台上传 PDF。发布需要当前知识库的写权限。
2. 上传后自动解析、整理并校验来源。无识别疑点的表格自动入库，完成后显示已入库与待核对数量；草稿仍不进入问答。
3. 仅有疑点的表格需要人工处理。左侧原件、右侧识别表格；点击单元格修改，支持补行和删除/恢复行。不要求填写原因，系统记录实际操作与来源位置。已通过来源校验的自动映射保留列名、单位和跨页关系。列名在右侧表格顶部直接修改，每列可调整文本/数字与单位；行菜单支持用某行作列名、删除和恢复。页面不展示解析器、哈希、原始 JSON、页面上下文与公式线索等技术信息；原始资料仍完整保留在后台。
4. 处理完成点击“确认并入库”，系统自动应用字段修改、重新校验后保存，无需另勾审核框或先手动预览。未定位到具体格子的整表标记合并为一次“已对照原件核对”，不捏造缺列/漏行结论；已定位的单元格显示右侧行列号并可一键定位修改。整表确认不放行未逐格处理的不确定单元格；跨页无共同标识的行对应仍需单独确认。可选“查看入库预览”。相同原件及相同计划重复发布得到同一表 ID。不同映射可以并存，模型不能重复累计重叠表。
5. 问答通过 `list_datasets.pdf_tables` 或 `list_pdf_tables` 发现已发布表；`read_pdf_table` 核对原值和逐格来源；`query_pdf_table` 根据真实列名执行只读 SQL。

“已确认”表示用户确认了映射计划，不保证 OCR 全部正确。草稿、查询结果均明确 `extraction_verified=false`；整篇 PDF 的表格覆盖始终为 unknown。不要把某几页的成功识别当作整份文档验收。

必要时点击右上角“重新解析”，使用当前服务配置读取原件。新结果形成独立草稿，保留旧结果和已发布表；只有完整通过来源与质量校验的表格才能自动入库。再次打开同一知识库 PDF 时，先验证当前访问权限与下载内容，再复用相同原件及解析配置的最新草稿。接口不允许浏览器指定解析服务地址或密钥。

## 跨页原则

- 每个页片段保留原始行列、标题、脚注、页码与坐标；只有表框坐标时标记表级精度，不伪造单元格坐标。
- 模型依据完整片段提出合并计划；程序不因页码相邻、列数相同或业务关键词自动认定同表。
- 各片段必须明确 `header_rows`，允许空列表。没有重复表头的第二页首行仍是数据；表头排除保留逐行操作记录。
- 每列必须覆盖每个片段，所有原始行要么成为数据，要么有明确的排除记录。排除数据行后 `input_complete=false`，不能声称全表统计。
- 跨页拆行只允许明确指定的前片段末行与后片段首行，逐列选择保留相同值、保留非空一侧或文本续接。禁止数字字符串拼接、静默覆盖不同值或猜测缺失值。
- 原始合并单元格及占位保留；无法明确归属的数据不能直接作为普通值参与计算。解析器仅给出合并后表且缺失页来源时拒绝将其当作已定位单元格。
- 公式保留 LaTeX/原始解析产物；本功能不把识别公式自动执行或当作电子表格公式缓存。

## 解析服务配置

配置在服务端，前端和问答参数不能指定 URL、凭据或解析引擎。默认关闭，界面明确显示服务未配置，不以普通文本回退伪装表格解析成功。

```dotenv
PDF_TABLE_PARSER_ENGINE=mineru_v1
PDF_TABLE_PARSER_URL=http://isolated-mineru-worker:8000
PDF_TABLE_PARSER_TIER=standard
# 如自建服务要求鉴权，再由部署环境注入：
PDF_TABLE_PARSER_API_KEY=
```

支持 `mineru_v1`（MinerU 4 的上传/任务/结果 API）、`mineru_legacy`（明确选择旧版 `/file_parse`）、`paddleocr_vl`（`/layout-parsing`）。只接服务端显式配置的目标，禁止重定向，不下载解析响应中的任意远程图片/产物地址。MinerU 使用返回的结构化 JSON/HTML；Markdown-only 产物不作为可计算单元格。

本仓库提供适配器，不把 OCR 模型打包进现有 docreader 容器。独立部署解析 worker，按真实 PDF 的中文、扫描质量、复杂表头与公式基准决定使用 CPU Basic 或更强的视觉版本。Basic 能启动不代表复杂扫描表格满足业务要求。解析版本未知时保留 null，不虚构版本。

默认单进程一次解析任务，输入 50 MiB；解析传输、ZIP 解包和产物有独立预算。任务状态写入当前授权目录；服务重启中断的任务明确失败，需要重试。此版本没有跨进程队列/自动恢复，也没有取消已开始解析或删除版本的界面。

## 数据与权限

所有原件、草稿、计划、确认记录位于现有 `WorkspaceRegistry` 解析的空间/知识库目录下 `pdf-tables/`。通过知识库原件导入时复用登录鉴权、所属知识库校验、下载前后元数据复核及原件 MD5；保存后用 SHA256 绑定 PDF、原始解析产物及计划。读取已发布数据时再次校验原件指纹。表 ID 不能跨目录访问。

结构化原件是导入时的独立快照，沿用现有工作台的知识库访问权限；知识库原 PDF 的后续删除不会自动删除该快照。原件变更需要重新导入新版本，不隐式替换已有结果。发布确认记录使用服务端认证身份；模型不能通过只读工具发布表。

SQL 只能读隔离内存表 `data`，禁用外部访问，限制输入行列、输出、内存与执行时间。缺失为 NULL；decimal 使用 DECIMAL(38,18)，超出可无损表达范围时拒绝，需保留 text。输出小数以字符串返回。输出分页不限制计算输入。

查询保留输入原件、计划和表记录指纹。返回 `_row_id` 只表示来源行引用；任意 SQL 表达式和聚合的逐格血缘未推断，结果明确 `sql_result_lineage_verified=false`。不能把 SQL 手动构造的 `_row_id` 当作表达式已获逐格证明。问答数值审核只使用实际结果值与明确计数，不把版面坐标、计划行号或来源哈希当作答案数字。

## 验收边界

协议夹具测试可验证权限、来源完整性、重复表头/无表头续表、空值/负数/小数、明确跨页拆行和 SQL 范围，不证明 OCR 识别正确。上线前须对真实授权 PDF 做逐格比对：漏行/漏列、空白与零、符号/小数点、单位/脚注、相邻不同表防误并、扫描件、公式和跨页拆格，并完成真实问答取数及引用验收。未取得真实样本不能声称已完成业务验收。
