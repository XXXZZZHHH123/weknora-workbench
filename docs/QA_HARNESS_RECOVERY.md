# 问答 harness 的证据恢复

## 问题与归因

当前系统已有 ReAct 工具循环、模型规划、上下文压缩、来源范围绑定、独立语义审核和确定性数值检查。验收失败不能概括为“没有 harness”，也没有证据证明只换模型就能解决。

| 问题 | 已核实原因 | 通用改造 |
|---|---|---|
| 跨文档回答缺关键来源，反复改写后失败 | 检索预算和读取范围不等于目标资料全部读完；拒绝反馈没有明确恢复类型 | 审核模型区分补证据与改写；补证据回到完整真实工具循环，再次审核 |
| 超长命中正文未完整读取 | chunk 分页不能解决单个 chunk 内的正文截断；后续模型视图还可能再次裁剪 | Unicode 正文分段、显式完整性和可继续的源 chunk 偏移；物理页内坐标独立说明 |
| 领域概念被过度拒答 | 将“资料中的断言需有来源”扩大为“通用定义也必须逐字存在于文件” | 模型区分已标注的通用解释、上下文推断和来源特定事实；显式仅据原文要求仍优先 |
| 常数被称为公式缓存 | 查询结果无条件附加公式缓存警告 | 按实际查询范围的公式记录计数生成元数据，不改变数值、不重算公式 |
| 已入库工作表被称为待确认 | 字段的单位待核对状态与工作表入库状态未清楚区分 | 目录明确已有已导入系列；单位状态与待导入目录分别呈现 |
| 表头单位为空后遗漏文件其他单位证据 | 原生图表的轴/标题及单元格引用缺少定向读取入口 | 原件检查按显式真实范围返回相交图表的文本和引用；由模型判断适用性，不自动写单位 |
| 图表密集文档导入膨胀 | 入库阶段预先生成全部可识别曲线的几何估读并写入索引 | 保留原始文字、标签、图像和绑定；详细几何通过已授权原图按需读取 |

以上是相互独立的机制问题。某些失败轮已有部分正确证据而模型未采用，不能全归因为工具漏发；空白页面、精确引用页预览及图片占位的根因尚未证实，单独留在验收限制中。

## 运行协议

独立审核仍检验完整任务、来源含义、范围、单位及引用，程序继续执行权限、真实 ID、参数和数值检查。审核器只返回受 schema 验证的判定与短反馈；`next_action` 可为 `revise_answer` 或 `collect_evidence`，接受时不得同时要求恢复。旧的只含判定/反馈响应保持兼容。

`collect_evidence` 不执行审核器写出的工具命令，也不将反馈作为事实。运行时恢复原人类对话及实际工具调用/结果，去掉独立重写的草稿信封，恢复用户所选推理参数和已经授权的完整能力。模型根据真实任务和缺口自行决定补读的文档、页、正文位置或计算步骤。之后仍须再次核验才能交付。恢复预算独立有界；达到上限不能解除来源保护或输出未通过的草稿。核验服务协议异常的独立重试和答案修正预算保持分离。

正文续读使用真实源 chunk 身份和 Unicode 字符偏移。物理页读取先裁切页内文本，再确定该文本的偏移；不能把 chunk 序号当页号。模型视图裁剪时也必须告知实际展示长度和续读位置，不能跳过未展示的文字，不能把部分内容报告为完整页。

详细图像审核规则仅在运行时有实际绑定的图像观察时加入；这按真实证据能力分层，不通过问题词识别“图表题”。独立重写视图保留有角色和省略标记的最近对话，用于理解代词和后续要求；历史助手内容继续不是数值来源。

## 评审上下文与阻塞标准

来源评审后的普通完成检查，使用运行时记录的精确信封身份还原真实用户对话及后续工具/用户消息；不按 JSON 形状猜测或剥除用户输入。匹配失败保留实时对话，避免丢失用户修订。重写与评审共用有界对话投影，排除最后一条用户消息之后的当前助手计划，保留早先答案用于理解追问，并显式标明省略。

来源事实投影排除成功的纯工具说明结果，能力另由真实注册目录提供；失败反馈仍保留。仅当成功结果的 Data 序列化与 Output 去空白后的 JSON 字节完全相同时，去掉评审视图中的重复 Output，持久化结果及数值校验不变。

评审拒绝应对应任务未完成、事实/单位/范围/来源错误、无依据结论或用户明确约束；准确相关的简短解释不因“未明确要求”单独阻塞。多份来源冲突时，文件名、上传顺序或数值接近不能证明权威版本、替代关系或指标等价，模型须依据实际证据判断，否则保留冲突。

首轮记录的待处理边界包括：审核期间新增用户修订前的当前助手消息，可能被通用角色投影视为先前答复；迭代耗尽的独立合成路径尚未统一使用信封还原。第二轮采用独立的本轮人类对话状态，并覆盖耗尽及停滞路径，设计见 [RESEARCH_HARNESS_DESIGN.md](RESEARCH_HARNESS_DESIGN.md)。下节保留首轮历史结果，不作为第二轮当前状态。

## 首轮历史验证结论（2026-10-16）

Go agent 与 modelcontext 回归通过；缺 ensurepip 的既有环境测试明确跳过。结构化全套、原图解析器与相关服务检查通过，最后单位提示修正另跑相关19项并验证真实接口加载。开发运行二进制与构建产物哈希一致，原暂存补丁保留。

真实问答仍有多来源归并、缺来源回答及机构解释的核验失败；字段单位证据利用也未通过最后单题复验。隔离跨领域回归多数可用，但存在内部标识暴露与概念例子边界问题。代码测试通过不代表端到端质量全部通过。

正常删除测试来源后还发现共享 Wiki 正文的语义残余。通过正常版本接口恢复受影响页并核对正文及同步片段，仅清理本次测试数据；通用 Wiki 撤回算法仍需修复。图片转换超时与精确引用页浏览器验收也没有据此宣称解决。逐题原始记录、模型对照及残余问题保存在本轮私有交付报告。
