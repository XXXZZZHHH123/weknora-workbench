# 个人库与 default 库的指标去重

状态：设计，待接入数据商 API 时实施。依赖 [中心来源与研究工作台](CENTRAL_DATA_SOURCES.md)。

## 目标

研究员个人知识库（自己上传的原表）和 default 库（空间的中心数据集，将来由数据商 API 持续更新）中常有相同的指标。研究台目录中同一指标只出现一次，默认使用 default 库的序列；相同与否由统一的确认流程决定，不由程序按名称自动合并。

## 一、找候选（只用于召回）

1. **数据商编码**（强候选）：default 库按 API 登记每个指标的数据商编码（如万得经济数据库 `S0049502`、钢联 `ID01218978`）；个人库字段的表头、字段说明或导入映射中带有相同编码时列为候选。编码从明确的字段元数据读取，不从名称中猜测。
2. **名称、单位、频率相近**（弱候选）：只作为补充召回，必须经过数值核实与人工确认，不能单独成立（`AGENTS.md`）。

## 二、程序核实

对每个候选对，程序给出可复核的证据：

- 重叠日期的观测逐期比较，数值按个人库原表显示的小数位四舍五入后比较，给出一致期数、不一致期数及最近不一致的日期；
- 单位、频率是否一致（不做单位换算）；
- 两边的数据截至日期。

## 三、统一确认

- "指标对应确认"页：形式与表格核对页一致，按个人库来源与工作表分组列出候选及证据。
- 编码相同且重叠期全部一致的候选可批量确认；存在不一致、缺编码或单位频率不同的候选逐条决定：**以 default 库为准**、**保留两者**、**不是同一指标**。
- 每条决定记录确认人、时间、证据快照，可撤销；撤销后恢复两者并列。
- 对应关系按空间保存，空间内所有研究台共用；确认权限同中心来源维护权限。

## 四、确认后的效果

- 研究台目录中该指标只显示 default 库版本；个人库字段作为副本保留，可追溯，但不出现在默认列表、自选候选与核心关注建议中。
- 已有图表、研判、策略、PPT 绑定若引用个人库字段，提示"改为引用 default 库指标"，研究员确认后生成新修订；不静默替换历史版本。
- default 库停更而个人库有更新观测时，在指标页提示，不自动切换来源。
- 未确认的候选保持两者并列，并在目录中提示"可能重复，待确认"。

## 五、数据结构（草案）

`indicator_equivalences`（按空间）：个人库字段身份（知识库、原件、字段）→ default 库指标身份、状态（`pending` / `confirmed_default` / `keep_both` / `rejected`）、证据快照、确认人与时间、撤销记录。研究事实目录读取时应用已确认的对应关系；原始字段与观测不改写。

## 六、前提与验收

- 前提：default 库通过 API 接入，并按数据商编码登记指标。
- 验收：编码相同且数值一致的候选能批量确认；不一致候选不能批量确认；确认后目录只显示一份、引用改写须人工确认；撤销可恢复；全过程不按名称自动决定。
