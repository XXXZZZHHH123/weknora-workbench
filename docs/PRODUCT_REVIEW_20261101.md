# 产品体验与测试审核 · 2026-11-01

## 结论

项目已经具备有价值的资料、结构化计算和研究工作台基础。开发环境本轮验证了真实上传、自动处理、两种问答模式、负数与缺失值处理、PDF 表格查询和原文引用。下一阶段应优先提高业务可用性、识别覆盖透明度和结果核验效率，再扩展研究功能。

目前不能依据本轮结果宣称生产业务链路全部通过：生产与开发版本不同，生产运行日志存在升级后的真实业务失败记录，本轮没有登录生产重新执行这些业务请求。

## 范围与方法

- 开发端口：18190。根源码分支 `feature/parse-fair-admission`，提交 `f21b5b9`；运行二进制不能仅由挂载源码或分支推断。前端截图及 API 结果来自实际运行服务。
- 生产端口：18090。实际 app 镜像为 `production-c97b4b03ac1985b5fc15827cc26932bc8aec01fe-41009408235-1`。生产只做容器、日志与数据库状态的只读检查。
- 新版源码对照：独立工作树提交 `04de380d39d66e5c2c361ffaac21fe48c9491552`。它用于核对缺陷是否仍存在于升级分支，不能代替生产浏览器验收。
- 使用既有开发测试账号，创建一个隔离知识库、4 份合成文件和 3 条测试会话。没有修改已有业务文档、模型配置或生产数据。
- 浏览器实际请求运行服务，没有模拟业务响应。检查桌面、390px 窄屏、刷新恢复和引用点击；另外检查源码与真实模型执行记录。
- 本轮完成审核与建议，没有实施业务代码修复、构建、部署、提交或推送。报告自身是新增文件。

## 问题、建议和验收标准

P1 表示优先排查或修复，P2 表示随后改善。以下将确定缺陷、实测能力边界、体验改进和待复验风险分开说明。

### F1 · P1 · 生产业务链路存在失败证据，需专项复验

证据来自当前生产 app 容器日志，集中于 2026-10-30 14:32 的一次请求链路：

- 模型调用返回 403，错误类别 `AccessDenied.Unpurchased`，标题生成和问答调用均出现失败。
- 结构化工具读取返回 HTTP 401。
- PostgreSQL 关键词检索报 `Unsupported query shape`，检索记录明确降为部分结果。

这些是同一链路中的多条日志，不是对应数量的独立用户故障；不能据此断言当前所有问题都会失败。另有同日浏览器能力端点 503，不等同于整个系统不可用。本轮没有重新调用生产模型或复现其授权问题。

建议：在与生产相同发布版本的隔离环境，分别复验主回答模型、标题模型、结构化服务身份传递和关键词检索。设置管理员可见的能力健康状态，把“模型无使用权限”“结构化服务鉴权失败”“检索仅部分成功”分开呈现。缺少结构化结果时不能把普通文本检索包装成完整统计结果。

验收：三条业务路径分别得到成功执行证据；故障注入时明确显示失败能力、受影响范围与恢复动作。仍然失败的能力不得显示正常。不要静默替换模型或放开鉴权。

### F2 · P1 · 推荐问题的开头年份被误删

真实首页多次出现“年1月至3月……”“/24年度……”等残缺问题。源码 `WeKnora/internal/application/service/knowledge_process.go:2534` 使用：

```go
strings.TrimLeft(line, "0123456789.-*) ")
```

该逻辑会连续删除所有开头的数字与相关符号，并不只删除列表序号。独立 Go 复现结果包括：

```text
2024年1月至3月的变化趋势如何？ -> 年1月至3月的变化趋势如何？
2023/24年度累计进度如何？     -> /24年度累计进度如何？
1. 2024年1月至3月的变化趋势如何？ -> 年1月至3月的变化趋势如何？
```

升级分支 `04de380` 的同文件第 2652 行仍有此逻辑。推荐问题属于模型生成内容，这里发现的是通用输出解析缺陷，没有据此断言存在业务问题硬编码。

建议：优先使用经过验证的结构化问题数组；兼容文本时仅解析明确的列表编号协议，保留问题正文。修复后对受影响的已保存推荐问题安排可追溯的重新生成，不能只修新数据。

验收：年份、跨年度写法、数字开头的合法问题和真正的列表编号均完整保留。测试样例只放隔离夹具，不进入业务意图判断分支。

### F3 · P1 · 数值回答的来源不能在最终正文直接打开

两条 Excel 回答计算正确，也写出文件名、工作表和 B2/B3/B4，但浏览器检查最终正文没有可点击的来源节点；Markdown 回答则生成了可点击的知识库引用。用户核对数值需要展开过程或另进表格页面。

这是来源可达性的体验缺口，不是“系统没有保存数值来源”。实际工具仍保留真实文件、单元格、查询及计算输入。

建议：为已验证的数值证据生成统一引用卡，点击即可打开原件、工作表和高亮单元格；聚合结果同时展示输入范围、有效值数、缺失数、公式及来源版本。引用由实际工具结果生成，程序验证权限和身份，不依赖模型自由拼写链接。

验收：从最终答案一步到达 B2/B3，刷新后仍可打开；权限不足明确拒绝；聚合输入范围与 SQL 实际范围一致。

### F4 · P2 · 原始文件名在结构化工作台丢失

上传 `audit-values.xlsx` 后，知识库目录保留原名，表格处理页的文件选择器和说明却显示随机十六进制文件名。导入记录与工具来源的 `source_file` 也使用该内部名。用户难以确认这是刚上传的文件。

源码链路：`structured-data/src/structured_data/ingestion.py` 使用随机临时路径；`imports.py:233` 取 `Path(path).name` 写入展示来源；真实原名虽在 `native_source_bindings.file_name`，未统一用于显示。升级工作树仍保留同类实现。

建议：内部存储键与展示名称分离，以已验证的原生文件绑定提供原名、知识库和版本。保留真实 ID、hash 与权限校验。

验收：目录、处理页、查询页、来源弹层与下载名称一致；同名文件用版本和上传时间区分。

### F5 · P2 · “已可查询”没有充分表达字段质量

合成 Excel 的表头是“收入（元）”，自动导入后字段目录仍为 `unit=null / unit_status=needs_review`，工作表整体显示“已可查询”。“备注”文本列也进入数值指标目录，有 3 条记录但 0 个有效数值。问答通过原件确认单位，本轮没有因此算错。

建议：同时展示可用性和质量，例如“可查询；1 项单位待核对”，并区分数值指标、文本维度、说明列。单位建议由模型根据完整表头和真实来源形成，程序校验证据、单位兼容性及计算范围；沿用现有安全门禁。

验收：单位未确认能明显看见；不能参与缺少依据的换算；备注列可作为筛选维度使用，不误导为可求和指标。

### F6 · P1 · 处理完成与内容覆盖必须分开展示

本轮两份 PDF 分别提供能力边界证据：无边框排版成功保存文字但识别到 0 张表；有边框表格自动入库 1 张表、数值正确。无边框样本的完成结果诚实返回“没有识别到表格”，没有假称成功；但用户若只看文件列表“已完成”，仍难判断是否满足查表任务。

建议：在列表和结果摘要显示“正文、图片、表格、可计算数据”的实际数量及覆盖状态。对可能存在未识别内容的页面，由模型基于真实页图评估并提供复核入口，原图、草稿和已发布版本分离保留。不能用页数、解析结束或模型一致意见代替完整性证明。

验收：无边框样本显示文字已处理、结构化表格为 0；有边框样本显示 1 张已可查询表；自动接受不显示成人工确认。真实复杂 PDF 仍需单独建立页级金标准后验收。

### F7 · P2 · 简单任务的调用与上下文成本偏重

短文档问题也执行了结构化能力发现，并发生一次来源未绑定的读取拒绝后恢复；三行数值查询也出现一次无效调用。累计 prompt 用量见上表。不能仅因小样本约十余秒即判定速度稳定，也不应把这些累计 tokens 当成一次模型窗口。

建议：沿用现有模型规划与按需工具展开，减少重复目录、schema 和来源内容；将执行阶段、有效工具耗时、模型等待、修复轮次和累计用量分别观测。来源绑定与数值保护继续执行。最终答复通过验证前可展示真实进度，不提前流出未核验结论。

验收：对固定隔离数据集做多轮基线比较，报告中位数/p95、首次状态/最终正文时间、错误恢复次数和累计用量；准确率、来源覆盖及权限不能退化。不得按问题词表、特定商品或验收题目走捷径。

### F8 · P2 · 读取范围被表述成原表有效范围

智能推理回答称“原表 A1:D4”，但下载的真实 Excel 只有 4 行 3 列，有效范围是 A1:C4。工具按模型请求读取 A1:D4，合法返回了空白 D 列；最终回答没有区分“读取窗口”与“原表有效范围”。本轮数值计算和 B 列来源正确。

建议：工具显式分别返回读取窗口、工作表有效范围和计算输入范围，答案引用相应属性，不把请求窗口作为原表结构事实。

验收：读取超出有效区域的空白列时，原表范围不扩张；计算输入依然精确绑定真实单元格。

### F9 · P2 · 窄屏首次打开时侧栏遮住大部分内容

390px 浏览器中侧栏默认展开，约占 260px，覆盖约三分之二屏幕；知识库和对话页主内容都被遮挡。页面整体没有横向溢出，也有手动收起按钮，因此不能称为完全不可操作。

建议：窄屏首次进入默认收起；展开采用抽屉与遮罩，选择目标后关闭，支持 ESC；桌面保留现有宽度偏好。先明确手机是否为正式支持场景。

验收：390px 首屏能看到完整任务入口和发送区，抽屉打开/关闭及键盘焦点恢复正常。

### F10 · P2 · 一次性任务被写为跨会话记忆

本轮 3 条合成测试会话被自动提取为 3 条任务记忆；问答还召回了既有、与当前合成文件无关的历史任务/兴趣。未发现它们改写本轮最终事实，但存在跨任务干扰和测试材料残留的风险。本轮生成的 3 条记忆已通过正常 API 精确删除，没有删除既有记忆。

建议：提供“本次临时研究，不写长期记忆”，区分长期偏好与一次性任务；展示本轮采用的记忆，允许明确排除。相关性和保留判断仍交由完整语义与来源证据，不新增业务关键词分类器。

验收：临时模式下不新增长期记忆；关闭、刷新、异步提取后均保持；删除来源或任务后的记忆生命周期对用户透明。

## 产品方向与新功能

以下是基于本轮观察提出的产品假设，尚未通过真实研究员访谈、转化数据或收益验证。项目已有项目、知识库、研究工作台、智能体及管理员反馈入口，不建议再新增平行入口承载这些能力。

| 方向 | 用户价值 | 建议落点与首版验收 |
|---|---|---|
| 证据型答案卡 | 快速核对结论是否可信 | 先解决 F3；同一张卡展示指标、单位、时间口径、真实来源版本、计算范围与缺失值，支持原页/单元格定位。 |
| 资料更新与结论差异 | 减少每周重复阅读和重做分析 | 基于现有版本管理，比较新增文件、数据修订及受影响结论，明确“原始数据变化”和“解释变化”；通知和订阅需用户主动开启。 |
| 可复用研究任务 | 保存研究方法与来源范围，降低重复配置 | 扩展现有研究工作台，保存来源绑定、口径、图表和交付格式；每次执行重新核验真实版本、权限和计算，不缓存固定答案。 |
| 研究假设与情景分析 | 把资料整理推进到可检查的研究过程 | 在现有工作台记录假设、支持/反对证据和待验证事项；情景计算区分真实数据、用户假设与模型解释。首版只做确定性敏感性分析，不承诺预测或交易收益。 |
| 反馈处理闭环 | 让反馈者知道问题是否得到处理 | 扩展已有反馈功能：反馈编号、我的反馈、处理状态和补充信息。新版源码已具备管理员列表/状态更新，不能把“增加反馈入口”当成尚未实现的新功能。 |

优先顺序：先处理生产链路复验、年份解析和来源可达性；随后统一状态、文件身份、单位与内容覆盖；再用证据卡、更新对比和可复用研究任务做小范围试用。任务式导航可围绕“添加资料 → 核对可用结果 → 提问核验 → 保存研究产出”，再通过真实用户试用判断是否需要调整现有信息架构。

## 尚未覆盖

- 生产登录后的上传、查数和真实模型问答；本轮开发成功不能替代生产验收。
- 大文件、复杂 OCR/跨页表、图表视觉准确率、Word/PPT 解析及文档生成全链路。
- 多人并发、公平排队、压力/容量、长任务中断恢复和备份恢复演练。
- 跨账号/空间/分享权限矩阵、安全渗透与全仓硬编码重新审计。
- 全仓自动化套件与远程 CI；本轮没有运行，因此没有声明通过。
