# 增量 Excel 导入与版本展示

2026-10-13，本地 Docker/Linux 验证。

## 问题与处理

此前确认一张工作表，会重新解析全部已确认工作表，并将完整记录集合留在 Python 内存中。棉花文件已有约 167 万条记录，触发单任务默认 768 MB 上限。

现在以导入记录对应的不可变快照为基础；若旧工具发布新版本却未更新导入指针，优先复用同一原文件、同一导入 ID 的最新快照，并同步其他表的已发布状态。在临时目录复制其 DuckDB，只删除本次修改工作表的记录，再插入经验证的新记录。未修改工作表不重新解析。首次导入按工作表逐次处理；原三表专用规则作为一个已明确的解析单元。解析记录及质量问题通过 JSONL/CSV 文件逐条传递到 DuckDB，预览只保留有限样本，质量报告只读前 200 项。内存保护、时间保护和任务停止后的临时目录清理继续有效。

全部检查通过、原文件副本的 SHA256 一致后，原子发布新目录。历史目录不修改。每个版本保留原 Excel、来源单元格、日期或期间来源、公式文本、缓存值、空白及错误状态。新增版本记录 parent_dataset_id 与 changed_sheets。规范化映射忽略浏览器区块 ID；相同文件和映射复用版本。

## 展示

- 业务文件选择框默认只展示每个文件的当前可用快照。
- 历史快照收进折叠的“处理历史”，可显式打开；页面提示当前正在查看历史，并使用该历史版本的原文件下载与查询。
- 开发验收样例和扫描记录单独折叠展示，普通查询目录与自动选数据集不包含样例；显式打开样例仍可核对。
- 兼容已有数据：只按三个已知开发样例的完整文件名识别，不按“验收”等泛化关键词排除业务文件。支持元数据 dataset_kind=business/sample 显式标记。
- 没有删除或覆盖历史快照及样例原件。

## 边界

这是同一原文件内工作表映射的增量更新；原文件内容变化时仍重新扫描及验证，不跨文件复用旧记录。不可变快照继续占用磁盘空间，历史折叠不等于删除或归档。单个异常巨大区块仍受资源限制，失败时不发布半成品。公式使用原文件已保存的缓存，不执行重算。上述实测仅代表该文件与当前本地环境。
