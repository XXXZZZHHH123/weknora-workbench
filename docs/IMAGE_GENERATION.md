# 在聊天中生成图片

图片生成通过智能推理智能体的 `generate_image` 工具执行。聊天模型负责理解用户需求，独立的生图模型返回图片；两者可以来自不同服务商。

## 配置

1. 在「设置 → 模型配置」选择「图片生成」，新增远程模型。
2. 选择 OpenAI 或通用 OpenAI 兼容服务，填写供应商的真实模型名称、Base URL 和 API Key。Base URL 通常包含供应商的 API 版本前缀，例如 `https://gateway.example/v1`；也支持完整的 `/images/generations` 地址。
3. 可选设置默认尺寸、质量、返回格式和超时。留空时遵循供应商默认值；这些值必须与所选模型支持的参数一致。图片生成超时为 30–600 秒，默认 300 秒。
4. 打开智能推理或自定义智能体，选择该生图模型，并勾选「生成图片」工具。主聊天模型仍选择聊天类型模型。
5. 在该智能体的聊天中描述需要生成的图片。成功后，结果卡和回答正文可以预览图片，附件支持下载。

保存配置不会发送付费生图请求，普通聊天连接测试也不会测试生图。需要在聊天中实际生成一次来验证服务商账号、模型权限和协议兼容性。

## 兼容接口

第一期只支持 OpenAI Images 风格的 `POST /images/generations`。请求包含 `model`、`prompt` 和固定的 `n: 1`，按配置或工具参数可附带 `size`、`quality`、`response_format`。供应商支持 OpenAI Chat Completions 不代表支持此生图接口。

响应须在 `data` 数组中返回一张图片，图片内容可以是 `b64_json` 或可访问的 `url`。程序检查真实图片内容、格式、尺寸和大小，支持 PNG、JPEG、WebP；最大 20 MiB、单边 8192 像素、总像素 32 Mi。

返回图片 URL 时，后端通过带 SSRF 防护的传输获取图片，不向该 URL 传递模型 API Key 或自定义鉴权头。内部部署地址继续遵循已有 SSRF 白名单配置，不会因生图功能放开内网访问。

## 保存和恢复

成功结果先写入文件存储，注册 `resource://` 资源句柄并绑定当前回复的消息产物，再向客户端报告交付成功。聊天记录只保留资源引用和元数据，不保存图片 Base64 或供应商短期 URL。预览和下载使用现有的鉴权接口。

每条助手回复最多提交一次生图请求；执行状态按真实租户、会话、消息和工具调用持久记录。同一执行重放不会重新生图。上游超时或连接中断时不自动重发，以免重复计费；如需再次生成，请发送新请求。已保存但尚未绑定消息的图片可以完成交付重试。停止本地生成不能保证供应商已取消或费用已退回。

刷新、切页和历史回放从持久消息产物恢复。图片保存失败会明确报告没有可下载图片；已归档图片不会因旧的结束或停止快照覆盖而消失。生成图片属于生成内容，不能作为知识库原图或事实证据。

第一期未提供图片编辑、参考图输入、批量生图或快速问答模式的独立生图执行路径。共享智能体不会获得使用源空间生图凭据的额外权限。
