# 模型自主分析与连续问答验收（2026-10-11）

## 范围与根因

本轮从 f24097859392e84741ea6b060e40dbb19fb9cf15 开始，在本地 Docker 调试；生产服务器未更新。主聊天模型及可选字段识别模型均使用本地配置的 deepseek-v4.1-flash。原文件 SHA-256 为 108b08e3f40b1f2cb081ca406fdc4bd02415dce5ffd2c7426d078c79573bd1fe。

系统原来已有 Agent 循环，问题在于结构化数据路径绕过了它：每轮强制调用 resolve_fields，拿到固定计划的答案就结束；解释上一轮时间、算法等请求也被改成重复查询。前端又用最后一张结构化结果卡片替代模型正文，因此即使模型尝试解释，用户仍看到原任务的答案。只给固定计划增加更多问题类型，不能解决这个结构问题。

## 实际修改

1. 删除强制单轮查询路径。主模型决定解释、检索、取数或组合分析，工具反馈回到正常 Agent 循环；resolve_fields 是可选工具。保留原始请求，并允许模型给字段工具传入当前子任务，避免程序用整句原话覆盖模型的分解。
2. 新增 analyze_table：隔离内存表只装载已授权文件版本的所选指标和日期范围。模型编写 DuckDB SELECT/WITH，程序执行分组、连接、窗口和多阶段计算，不新增按问题措辞分支的意图枚举。最多16个输入字段、50000条输入、500行展示结果、40列；外部访问关闭、单条语句、256MB内存、8秒SQL执行上限。输入超预算拒绝执行，结果展示截断明确说明。
3. 保存查询与分析事实：真实来源、实际和有效记录边界、条数、缺失、SQL和结果。get_result_evidence 可以读取历史事实；旧字段计划没有证据时只重执行原计划，不重新识别意图。
4. 结果先接受独立上下文复核，再检查数值来源。复核只接收原请求、近期用户要求、真实工具结果和标为未核验的草稿，不保留助手之前的解释链；仍可调用工具纠正。程序数值检查识别舍入、比例、日期及单元格格式，最多两次反馈修正。它只检查数字可追溯性，不能证明指标、口径或因果解释正确。
5. 用户通过界面提交的字段选择由服务器直接执行一次，再让主模型解释结果；模型不能伪造用户确认。技术错误返回可修正反馈，不自动转成字段确认。
6. 前端以模型最终正文为答案，原表结果和SQL依据折叠展示；已恢复的中间错误不替代最终回答。较新分析结果不被较早字段卡片覆盖。
7. 小型工具集可选择直接暴露定义，减少逐项发现工具的额外回合；默认延迟发现与执行权限校验保留。数据运行提示只对有实际数据工具的智能体注入。
8. 修复模型参数局部更新会清空模型 source/type 的缺陷，保留既有参数与凭据。本地为主模型配置 enable_thinking，并显式启用智能体 thinking；字段绑定维持短调用。另将已有协议层的 ThinkingBudgetTokens 接入智能体配置，预算由供应商适配器处理，不按问题类型决定是否思考。最终本地配置使用4096推理预算和8192 completion预算；原模型将DashScope地址配置为generic，已校正为aliyun以使用真实供应商参数。原配置保存于本地私有备份，未改凭据或生产模型。

这里使用的是现有 WeKnora Agent 运行框架，不引入外部 Claude SDK，也没有把测试问题或期望数字写入生产意图路由。测试题库和原表列号只用于验收。

## 测试方法

四个题库共31条请求：19条开放分析及连续追问、6条未列入首轮分析的问题、5条明确时间范围回归，以及1条引用实际错误回答的核对纠错请求。会话内依序提问，会话间隔离。test_real_users.py 保存真实 Agent SSE、工具入参/输出、最终回答、持久化消息及耗时；completed_ungraded 只表示请求结束，不能作为正确率。

agent_source_oracle.py 直接用 openpyxl 读取原文件缓存值，使用 Python 标准库独立计算，不通过被测字段服务、SQL或模型生成标准答案。所有失败回放保留在被 Git 忽略的 results 目录，未覆盖成成功记录。网页另抽查跨年合计、时间解释和缺失说明，不能声称30题均逐一通过网页操作。

### 调试中发现的问题及处理

| 问题 | 证据与处理 |

| 周均价被模型用错误日历分组 | initial 阶段生成了周五至周四的分组；分析工具明确DuckDB原生日期函数，禁止自行拼日历算法，但不规定用户应选择哪种业务周 |
| 中位数和差值由模型补算成错误数字 | initial/final 阶段出现17252.5、537.5；计算交给SQL并增加数值依据反馈，后续回放为17207.5、582.5 |

| 未请求的逆向变化率与单位推断 | composition-verified/AG-09 附带逆向变化解释；window-verified/AG-11用跨字段数值吻合推断单位。复核要求删除未请求的补充数字与无来源业务判断，不能把这些附加解释当正确答案 |

## 验收证据与边界

agent-v28-window-verified 和 agent-v28-composition-verified 保存一次数值正确的回放；但 release-analysis 的再次复测暴露周最高结论波动，不能据此前一次成功声称稳定通过。独立复核后的最终回放另记于下方，不把不同版本的通过项拼成最终100%正确率。

歧义年度仍需结合数据定义处理。“2021/23年度”本身可能是连续自然年范围、两个指定年份或业务年度；不能固定回答“两年整年”，也不能无来源断言棉花年度边界。用户明确“2022年1月开始、23年12月结束”后应执行整个范围并报告源文件缺月。累计量、快照和流量的可加性同样不能由记录频率证明。

## 运行与发布

本地入口：http://127.0.0.1:18080。只更新代码镜像不会自动更新数据库内已有智能体的提示词、模型与MCP目录；需使用该环境已有所有权标记运行register_weknora.py，明确model-id，按需--thinking，默认先预览。模型本身的thinking_control在模型设置中配置；脚本不会擅自修改共享模型或凭据。

生产仍手动update.sh。当前仅本地调试，不部署服务器；正式部署前应确认本报告最终回放与已配置模型，并保留旧镜像与数据恢复路径。复杂分析会增加推理和复核调用，耗时及费用仍需要继续评估，不能把有限题库验收解释成任意问题的正确率承诺。
