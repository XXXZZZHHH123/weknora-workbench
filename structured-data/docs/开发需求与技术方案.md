# WeKnora 结构化 Excel 数据服务：需求与开发方案

日期：2026-09-28。适用范围：中哲物产本地棉花数据试点。

## 一、目标

在 WeKnora 网页提问时，能够查询大型 Excel 中的准确数值、完成明确口径的计算，并返回原文件、工作表、单元格来源。数据导入不调用 Embedding；模型仅参与理解问题和解释查询结果。

首期输入为《棉花数据库(2).xlsx》中的“郑棉期货”“郑棉仓单”“中国棉花平衡表”。这三张表代表多层表头、日期序列、并排重复区块。其他工作表不自动冒充已支持。

## 二、用户流程

1. 通过结构化导入入口选择文件（首期同时提供本地导入命令和简单管理页）。
2. 查看识别出的工作表、指标、单位、日期范围、异常和来源信息。
3. 规则匹配的表自动整理；未知结构、缺失必要表头的表提示不支持或需要配置。
4. 导入成功后，在 WeKnora 中选择专用的“棉花结构化数据”智能体。
5. 提问单日数值、区间统计、两个指标差值。智能体调用数据工具取数，回答包含口径和来源。
6. 新文件按照文件内容指纹形成独立版本；重复导入相同文件不重复追加数据。切换版本须明确，旧版可追溯。

## 三、开发清单

| 模块 | 首期交付 | 后续扩展 |
|---|---|---|
| Excel 解析 | 三张表的明确规则、多层表头、日期、数值、空值、公式缓存状态 | 更多模板，辅助配置规则的界面 |
| 数据标准化 | 日期、指标、合约/地区/口径、数值、单位、来源单元格 | 跨供应商指标映射和单位换算 |
| 校验和追溯 | 文件 SHA-256、版本、重复键/异常记录、日期范围、来源定位 | 审核流程、数据修订对比 |
| 存储 | 每次导入生成完整 DuckDB 快照，成功后发布，失败不替换有效数据 | PostgreSQL、多租户、并发导入队列 |
| 查询与计算 | 指标目录、明确过滤条件的取数、区间统计、两项差值；参数化查询 | 多表关联、同比/环比、业务计算模板 |
| WeKnora 接入 | MCP 工具服务、独立智能体、中文工具说明、使用说明 | 原生上传页路由、报告和数据混合回答 |
| 管理页 | 查看数据集、导入进度/结果、指标目录与查询预览 | 批量文件、任务取消、定时刷新 |
| 图表 | 首期识别原生图表/图片存在情况，报告处理边界 | 图表数据引用映射、图片 OCR/视觉理解 |
| 测试 | 来源逐格核对、日期/指标错误防护、缺失数据拒答、真实工具接入 | 19 道棉花综合题及报告图表评测 |

## 四、技术栈

| 技术 | 用途 | 选择理由 |
|---|---|---|
| Python 3.12 | 结构化数据服务 | 方便处理 Excel、运行验证和编写业务规则 |
| openpyxl | 只读读取 Excel | 读取单元格、表头和公式缓存；不改原文件 |
| DuckDB | 本地结构化存储与计算 | 单机试点易部署，能够做确定性筛选与聚合 |
| FastAPI + Uvicorn | 管理页与导入/查询接口 | 独立服务，避免重编译现有 WeKnora |
| MCP Python SDK | 暴露模型查询工具 | 复用 WeKnora 的 MCP 接入能力 |
| 简单 HTML/JavaScript | 本地管理页 | 首期聚焦导入和核验，减少前端依赖 |
| pytest | 解析和查询回归验证 | 防止日期、单位、口径、来源被改错 |
| 现有百炼聊天模型 | 理解问题、调用工具、整理答案 | 复用现有配置，不新增 Embedding 需求 |

pandas 可在扩展复杂转换时引入，首期不为简单规则额外依赖它。图片理解属于后续能力，届时再配置视觉模型。

## 五、数据和工具契约

数据分为：数据集版本、指标目录、观测值、质量问题。每条观测值至少包含 series_id、日期、数值、来源工作表、来源单元格；指标目录保存指标名、维度、单位和表头证据。缺失值不是零，未知单位不猜测。

给模型的工具限定为：

- 查看数据集及指标目录：先确认范围、指标 ID、单位和日期覆盖。
- 按指标和日期查询：返回数值、记录数、是否截断和来源。
- 按明确规则统计或比较：使用数据库计算，返回过滤条件和参与计算的数据来源。

首期不接受模型提供的任意 SQL、文件路径或数据库路径。只开放参数化的已知查询操作，限定返回量。数据服务以服务密钥保护 MCP；只供本机测试账户使用。该服务不等同于完整企业权限系统。

## 六、准确性要求

1. 原始文件只读；导入前后指纹相同。
2. 日期字段保存为日期类型；合约和指标不依赖模型猜列。
3. 读取公式时使用工作簿保存的缓存结果；缓存缺失、Excel 错误值等作为质量问题记录，不自行假定已重算。
4. 日期超出范围、指标不存在、单位不明等情况明确返回，禁止补造数据。
5. 聚合区间的起止日包含在内；缺失数量与实际参与数量明确。
6. 差值必须明确“哪个减哪个”，来源可核对。
   单位未确认时，仅允许已核对模板中同一合约的收盘/结算原始数值比较，结果明确不附单位、不换算；其他未知或不一致单位的差值拒绝。
7. 并排重复区块必须区分口径，不把全部工作表按相同列名拼起来。
8. 数据时间范围与文件名称、修改时间分开；不能把旧工作簿当作实时行情。

## 七、验收标准

| 验收项 | 通过条件 |
|---|---|
| 解析 | 三张表支持的区域完成导入；排除区域和异常有清单 |
| 数据保真 | 核心点值与来源一致，源单元格可回查；原文件不变 |
| 计算 | 单日差值、区间均值/最大最小值与独立计算一致 |
| 失败行为 | 缺日期、错指标、跨单位差值等不返回貌似正确的结果 |
| 成本 | 本地导入不发聊天或 Embedding 请求 |
| 接入 | WeKnora 能列出并执行 MCP 工具，真实问答的数值和来源均通过核对 |
| 版本 | 同一内容重复导入不会重复累计，失败导入不损坏有效快照 |
| 性能 | 实测并报告三张表导入时间、行数、查询耗时；不提前承诺秒级全表处理 |

测试报告使用“问题是什么—预期答案是什么—实际返回什么—差距是什么”。工具测试与真实 LLM 问答分别记录，接通不等于准确率达标。

## 八、开发顺序和范围边界

第一阶段（本轮）：形成方案，实现三表解析、存储、受控查询、管理页和 MCP 接入，完成来源验证和小范围问答验证。

第二阶段：扩充其余工作表规则，完善图表引用提取、增量更新和业务计算模板。

第三阶段：将结构化导入整合进 WeKnora 原生页面；补齐多人权限、审计、备份、任务队列及生产部署。

首期不承诺任意 Excel 自动理解、不重建现有知识库、不重新触发整本 Excel 向量化。已有知识库和正在运行的用户任务不由本试点主动删除或取消。
