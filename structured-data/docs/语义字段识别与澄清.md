# 语义字段识别与澄清

## 现在的流程

1. 用户在 WeKnora 选择“表格数据分析（结构化）”提问。
2. 字段识别服务向已配置的百炼聊天模型发送当前已导入目录：真实表名、指标名、单位、维度，以及本轮问题和上文指标。无整表数据、无 Embedding。目录用短编号和按工作表分组压缩，不删减当前目录中的列。
3. 模型判断查数或计算，并从目录中提出候选。大目录中涉及计算或歧义的方案，再用小范围候选及相邻字段复核，减少无关候选和遗漏的计算输入。连续追问先比较上文所在表，找不到候选再扩大范围。程序校验所有编号必须属于实际数据集。
4. 明确的方案由程序取数；计算使用有界的 Decimal 四则解释器，不执行模型代码或自由 SQL。原值、缺失状态和原单元格保留。
5. 有歧义的方案返回 needs_clarification，执行器拒绝取数。WeKnora 显示真实候选单选和自由文字弹窗。
6. 用户选择后，confirm_fields 校验选择范围。计算方案根据所选列重新核对公式和单位；仍不明确就继续问。
7. 网页最终数值直接展示结构化工具结果，避免聊天模型在复述时改写数字。

## 使用边界

- 移除了搜索中自动生成“汇率→美元兑人民币/其他币种”的规则。显式保存的别名仍可用于字面目录搜索；主要问答走大模型理解。
- 原 convert_price 工具保留用于兼容，其支持币种限制是计算校验，不参与新语义字段选择。新流程按实际候选及四则公式计算。
- 同一文件默认最新已导入版本；多文件必须先确定文件。未导入的页不会作为可取数来源。
- 单日点值和有界四则计算已接入自动流程。期间标签与区间统计保留 query_series；尚无任意复杂统计计划编译器。
- 模型可能误判字段或业务口径。澄清触发依赖模型判断，不是数学置信度保证。程序保证候选真实、待确认方案不可执行、计算按给定表达式完成；尚未实现通用量纲验证，不能保证模型提出的所有公式都符合业务含义。
- 目录超过 55,000 字符时要求缩小文件/工作表范围，不静默截掉列。当前 492 指标目录可处理。
- 本地试点沿用现有单工作空间权限；不是多租户生产权限系统。确认请求通过聊天用户回复传递，尚非独立签名的人机审批凭证。
- 此数值保护覆盖本次定制的 WeKnora 网页聊天；直接消费 WeKnora API 的下游必须以工具返回的 answer 为准，不能仅信模型 final_content。

## 模型与费用

沿用 .private/model-config.json 的 chat 配置（当前 qwen-max）。首次语义识别会调用聊天模型；同问题、目录、上下文和版本有缓存。大目录复杂问题会多一次小范围复核；确认计算候选后也会再调用一次以核对所选列的计算方案。不需要重做表格向量化。费用取决于目录规模和模型计费，未测算实际账单。

## 部署

Python 服务源码挂载在 structured-data/compose.yml，修改后重启 cotton-data。工具注册用 scripts/register_weknora.py --apply。

前端在 WeKnora/frontend：npm ci，然后 VITE_IS_DOCKER=true NODE_OPTIONS=--max-old-space-size=4096 npm run build。

本地覆盖镜像：在 structured-data 运行 docker build -t weknora-eval-ui:field-resolution -f deploy/Dockerfile.frontend ../WeKnora/frontend/dist。

compose.test.yml 的 frontend 指向上述镜像，重建 frontend 容器即可。回退时改回 wechatopenai/weknora-ui:v0.8.2。原数据库和源文件无需变更。
