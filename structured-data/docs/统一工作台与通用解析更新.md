# 统一工作台与通用解析更新（2026-10-08）

## 使用入口

打开 http://127.0.0.1:18080/platform/structured-data ，登录一次 WeKnora 后，点击左侧“结构化数据”。上传、映射确认、图表引用、查询预览均在主页面内操作。原 18082 入口保留用于兼容；日常使用新入口即可。

右上角“AI 模型设置”，或映射表单中“当前配置的模型（点击修改）”，进入同一个设置页。这里设置的是结构化服务用于 **映射建议和字段理解** 的聊天模型。WeKnora 智能体对话模型仍在 WeKnora 的模型管理中配置，二者用途不同。

模型设置支持 OpenAI Chat Completions 兼容接口：填写模型 ID、API Base URL、API Key；密钥留空表示保留。页面不回显密钥。保存后下一次调用生效；无需重新导入、向量化或重启。

## 本次修复

1. 原生图表：四位数字标签不再一律解释为年份。连续年份组和明确“年”标签会进行年份核验；其他标签保留原文。每条曲线具有独立查询范围，日期使用源表已验证日期。不会因为点击“1901”而查询公元 1901 年。
2. 合并表头：根据 Excel 实际合并单元格范围继承上层标题和明确单位，保留上层与子表头的来源坐标。不会将销售额、销量、均价混成一个产品指标。复杂表头仍要预览确认。
3. 已上传文件可点击“更新待确认表的识别建议”。仅刷新规则版本变化的待确认候选，保留已确认映射与历史数据集，不必重新上传原文件。
4. 通用包目录改为 `src/structured_data`，CLI 为 `structured-data`，服务名为 `structured-data`。既有棉花三表规则移入可识别的历史布局配置 `profiles/cotton.py`，通用解析流程不依赖棉花品类。历史数据、审计版本、旧环境变量兼容入口保留。
5. WeKnora 新增工作台路由与侧栏入口；同源内嵌页面复用当前登录令牌。结构化 API 每次向 WeKnora 核验身份，拒绝未登录、过期令牌和其他租户。当前单数据目录仍限于已配置的租户 10000，尚未扩展为多租户数据存储。

## 运行与配置

- WeKnora 前端：18080；API：18081；结构化服务：18082。
- 前端镜像构建：在 `structured-data` 目录执行 `bash scripts/build_frontend.sh`，再使用根目录 WeKnora Compose 配置更新 `frontend`。
- 服务容器：`weknora-structured-data`；Compose 项目：`weknora-structured`。
- 在 `structured-data` 目录运行：`docker compose -p weknora-structured -f compose.yml up -d --no-build --pull never`。
- 新环境使用 `docker compose -p weknora-structured -f compose.yml up -d --build`；根目录 Dockerfile 安装通用包。当前本机离线更新复用旧镜像依赖，入口显式为 `python -m structured_data.cli`。
- 原数据目录仍为 `structured-data/data`。模型页面的覆盖配置写入其中的 `model-settings.json`（0600）；未保存页面设置前读取 `STRUCTURED_MODEL_CONFIG` 所指的现有配置文件。
- WeKnora 原 MCP 和智能体 ID 保持不变，MCP 地址更新为 `http://structured-data:18082/mcp`，9 个工具已通过连接检查。旧所有权标识和网络别名仅用于兼容迁移。
- 后端仍作为独立服务运行；用户操作入口和登录已统一。
